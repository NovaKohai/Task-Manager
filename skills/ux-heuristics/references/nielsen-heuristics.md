# Nielsen's 10 Usability Heuristics

## 1. Visibility of System Status
Keep users informed through timely feedback.

**Good:** Progress bars, confirmations, loading indicators, skeleton screens.
**Bad:** Silent failures, no response to button clicks, stale indicators.

## 2. Match Between System and Real World
Speak users' language.

**Good:** "Sign in" not "Authenticate", "Search" not "Query", trash bin icon for delete.
**Bad:** Technical jargon, industry acronyms without explanation.

## 3. User Control and Freedom
Provide clear "emergency exits."

**Good:** Undo, cancel, back button, close button on modals.
**Bad:** No way to undo, confirmation dialogs on everything, broken back button.

## 4. Consistency and Standards
Same words, styles, and behaviors mean the same thing.

**Good:** Same term throughout (always "Projects" not mixed with "Workspaces"), platform conventions followed.
**Bad:** Same action called different things, different actions look identical.

## 5. Error Prevention
Prevent problems before they occur.

**Good:** Constrained inputs (date pickers), autocomplete, sensible defaults, unsaved changes warnings.
**Bad:** Allowing invalid data entry, no confirmation for destructive actions.

## 6. Recognition Rather Than Recall
Minimize memory load - show options, don't require memorization.

**Good:** Breadcrumbs, recent searches, pre-filled fields, dropdowns with decoded values.
**Bad:** Requiring users to remember numbers, codes, or navigation paths.

## 7. Flexibility and Efficiency of Use
Serve both novices and experts.

**Good:** Keyboard shortcuts, bulk actions, saved searches, command palettes (Cmd+K).
**Bad:** No shortcuts for power users, forcing experts through beginner flows.

## 8. Aesthetic and Minimalist Design
Every element must earn its place.

**Good:** One primary CTA per page, clear visual hierarchy, ample whitespace.
**Bad:** Everything screaming for attention, too many options, decorative clutter.

## 9. Help Users Recognize, Diagnose, and Recover from Errors
Error messages need three parts: what happened, why, and how to fix it.

**Good:** "Password must be 8+ characters" not "Invalid", preserved input after error.
**Bad:** "Error 500", "Invalid input", blaming the user.

## 10. Help and Documentation
Help should be searchable, task-focused, and contextual.

**Good:** Tooltips, inline hints, guided tours, searchable knowledge base.
**Bad:** Manuals nobody reads, help hidden behind menus, generic documentation.
